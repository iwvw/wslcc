# 用户故事与任务场景

## 1. 用户故事

### 1.1 环境与入门

- US-01：作为 Windows 开发者，我希望打开应用即看到 wslc 与内核版本、缺失组件和活动会话，以便快速判断环境是否可用。
- US-02：作为开发者，我希望在组件缺失或版本过低时看到明确的升级命令提示，而不是晦涩的错误码。
- US-03：作为企业用户，我希望看到原生 API 是否可用、当前走的是哪条数据通道，以便理解功能差异。

### 1.2 镜像管理

- US-10：作为开发者，我希望以列表方式查看本机镜像（名称、标签、大小、创建时间），以便选择要运行或删除的镜像。
- US-11：作为开发者，我希望输入镜像名并点击拉取，界面实时显示拉取进度与结果，成功后列表自动刷新。
- US-12：作为开发者，我希望选中镜像即可删除，删除前有确认，删除失败时看到原因。
- US-13：作为开发者，我希望在镜像拉取/删除失败（例如镜像仓库网络受限）时看到可读的错误信息。

### 1.3 容器管理

- US-20：作为开发者，我希望列表展示容器（名称、镜像、状态、端口、启动时长），running 与 stopped 一目了然。
- US-21：作为开发者，我希望用表单新建容器（名称、镜像、端口映射、环境变量、自动删除、后台运行），无需手写命令。
- US-22：作为开发者，我希望对选中的容器一键启动、停止、重启、删除，操作成功或失败有明确反馈。
- US-23：作为开发者，我希望查看容器日志，以排查运行问题。

### 1.4 会话管理

- US-30：作为开发者，我希望配置会话名称、存储路径、CPU 与内存配额，并且配置被持久化。
- US-31：作为开发者，我希望看到当前活动会话列表，知道哪些 VM 会话在运行。

### 1.5 可观测与审计

- US-40：作为管理员，我希望所有在界面里完成的操作（拉取、新建、启停、删除）都有审计记录，含时间、类别、动作、结果与耗时。
- US-41：作为管理员，我希望查看镜像拉取历史，含仓库、总量、是否成功。
- US-42：作为开发者，我希望应用重启后设置、历史、快照仍在。

## 2. 任务场景（端到端）

### 场景 A：新手体检

打开应用 → 仪表盘显示 wslc 2.9.10、内核 6.18、组件齐全、0 个活动会话 → 进入镜像页 → 本机无镜像 → 输入 alpine:latest → 拉取成功且出现进度 → 列表出现 alpine:latest。

### 场景 B：运行一个 Web 服务

镜像页确认 nginx 已存在 → 容器页点击新建 → 名称 web、镜像 nginx:latest、端口 8080:80、后台运行 → 创建成功 → 列表出现 web（running，8080:80） → 停止 → 状态变为 exited → 删除。

### 场景 C：故障排查

某容器停止失败 → 界面 InfoBar 显示可读错误（包含 wslc 错误码）→ 仪表盘显示当前数据通道 → 活动页看到该次操作的失败记录与耗时。

### 场景 D：配置持久化

在设置页把会话名称改为 wslc-prod、存储路径指向 D:\wslc-data、内存 8GB → 重启应用 → 设置仍保留 → 新会话按该配置工作。

## 3. 约束故事

- US-50：作为运维，我希望应用在没有 Docker Hub 直连的网络下启动不崩溃，拉取失败仅导致该操作报错。
- US-51：作为开发者，我希望应用构建产物不含编译器警告。
