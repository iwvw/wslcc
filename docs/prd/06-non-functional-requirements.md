# 非功能需求

## 1. 性能

- 应用启动：从进程启动到主窗口可交互不超过 3 秒（本地数据加载）。
- 列表刷新：镜像/容器列表单次刷新不超过 2 秒（wslc 命令执行时间为主，界面不得冻结）。
- 长操作（拉取/运行）异步执行，UI 持续响应，提供进度反馈。
- 数据库操作毫秒级，绝不阻塞 UI 线程。

## 2. 可靠性

- 任何 CLI/API 异常不得导致应用崩溃；统一捕获并转为可读错误展示。
- 应用重启后设置与历史数据完整可读（SQLite 持久化）。
- wslc 命令不可用（进程不存在、版本过低、VM 会话异常）时，界面仍可浏览数据库内容。
- 不假设网络可用：镜像仓库不可达时仅对应操作失败。

## 3. 安全

- 不存储凭据；注册表登录等敏感操作不纳入 v1 范围。
- 审计日志不记录敏感参数（端口映射/环境变量值可记录键名）。
- 数据库位于用户本地配置目录，不写入应用安装目录。

## 4. 可维护性

- 分层清晰：App（UI）→ Core（服务）→ Data（存储），单向依赖。
- 服务接口化（IWslc*Service），便于替换实现与单元测试。
- 所有编译器警告清零（含 MVVMTK0045，使用 partial property）。
- 构建命令可重复、可脚本化（见 ADR-0007 MSBuild 构建方案）。

## 5. 可观测性

- 全局未处理异常写入 `%LOCALAPPDATA%\WSLCC\app-crash.log`。
- 所有写操作进入审计日志（类别/动作/详情/结果/耗时）。
- 镜像拉取历史可回溯（引用/状态/起止时间/错误）。
- 仪表盘展示数据通道（原生 API 可用性），便于定位功能差异。

## 6. 兼容性

- 运行目标 Windows 11；最低目标平台 10.0.17763。
- wslc 输出字段变化时，JSON 解析采用多候选字段名容错，避免单字段缺失导致整体失败。
- WSL 预发布版 API 不稳定已知（本机环境实测）：应用以 CLI 为主通道，规避原生 API 会话层 E_UNEXPECTED。

## 7. 本地化

- 界面文案使用简体中文。
- 错误消息保留 wslc 原始错误码（如 E_UNEXPECTED），便于对照官方 issue。
